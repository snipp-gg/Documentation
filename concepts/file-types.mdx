## Supported formats

Snipp supports a range of image and video formats for uploading and sharing. Ultra accounts and teams can also upload archives, audio and PDFs.

### Images

| Format | Extension | MIME Type |
|--------|-----------|-----------|
| PNG | `.png` | `image/png` |
| JPEG | `.jpg`, `.jpeg` | `image/jpeg` |
| WebP | `.webp` | `image/webp` |
| GIF | `.gif` | `image/gif` |

### Video

| Format | Extension | MIME Type |
|--------|-----------|-----------|
| MP4 | `.mp4` | `video/mp4` |
| MOV | `.mov` | `video/quicktime` |
| MKV | `.mkv` | `video/x-matroska` |

<Info>
  All uploaded videos are automatically remuxed to MP4 with the `moov` atom
  moved to the start of the file (faststart). This allows browsers to begin
  playback before the full file has downloaded. `.mov` and `.mkv` uploads
  are stored as `.mp4` after processing, and the share URL reflects the
  new extension. If remuxing fails, the file is rejected as corrupt or
  unplayable.
</Info>

### Files (Ultra)

| Format | Extension | MIME Type |
|--------|-----------|-----------|
| ZIP | `.zip` | `application/zip` |
| 7-Zip | `.7z` | `application/x-7z-compressed` |
| RAR | `.rar` | `application/x-rar-compressed` |
| Gzip | `.gz` | `application/gzip` |
| TAR | `.tar` | `application/x-tar` |
| XZ | `.xz` | `application/x-xz` |
| Bzip2 | `.bz2` | `application/x-bzip2` |
| Zstandard | `.zst` | `application/zstd` |
| MP3 | `.mp3` | `audio/mpeg` |
| WAV | `.wav` | `audio/wav` |
| FLAC | `.flac` | `audio/flac` |
| Ogg | `.ogg` | `audio/ogg` |
| Opus | `.opus` | `audio/ogg; codecs=opus` |
| AAC | `.aac` | `audio/aac` |
| M4A | `.m4a` | `audio/x-m4a` |
| PDF | `.pdf` | `application/pdf` |

Files are available on Ultra and in teams. On other plans they fail with type `unsupported_type`, like any other unsupported format. Executables and app packages (`.exe`, `.msi`, `.dmg`, `.apk`, `.jar` and similar) are never accepted.

<Info>
  A post that contains a file is never public. If any file in an upload request is one of these, `post-privacy: public` is applied as `unlisted` to every post the request creates, and `post.privacy` in the response says so. [Update Post](/api-reference/endpoint/posts/update) returns `403` with type `forbidden` and `Posts with files cannot be made public.` when you try to make one public, and [Add Files](/api-reference/endpoint/posts/add-files) rejects files on a public post with `unsupported_type`. File URLs are always signed and expire after 24 hours, whatever the post's privacy, and download under the file's original name.
</Info>

## Discord bot uploads

The Snipp Discord bot is invite-only. Add it to your server or as a user app from [snipp.gg/bot](https://snipp.gg/bot). There is no HTTP endpoint for the bot.

The bot accepts images only (`.png`, `.jpg`, `.webp`, `.gif`). Videos are **not supported** through the bot. Upload those from the [web uploader](https://snipp.gg/upload) or the [`/upload` endpoint](/api-reference/endpoint/upload).

## File size limits

Maximum file size depends on your plan:

| Plan | Max File Size |
|------|---------------|
| Free | 50 MB |
| Plus | 20 GB |
| Ultra | 50 GB |
| Teams | 50 GB |

Plus and Ultra have no per-file cap beyond your weekly quota: a single file can use the whole week's allowance (20 GB on Plus, 50 GB on Ultra). Uploads to a team are capped at **50 GB per file**. A file larger than your plan's limit fails with type `file_too_large` and `File size exceeds the 50 MB limit.` (20 GB on Plus, 50 GB on Ultra and team keys), like any other per-file failure. When it is the only file in the request the status is `413`. When the whole request's declared size already exceeds your weekly quota, it is refused up front with `413` and the same message.

<Info>
  Videos have a hard ceiling of **30 GB** per file. It only applies on Ultra and in teams, since Plus is already capped at 20 GB and Free at 50 MB. A larger video fails with type `file_too_large` and `Video exceeds the 30 GB limit.`, with status `413` when it is the only file.
</Info>

<Info>
  Upgrading to [Plus](https://snipp.gg/pricing) removes the 50 MB per-file cap. Upload anything up to your full weekly quota in a single file.
</Info>

## Unsupported files

The type is detected from the file's own bytes, not its name or the declared content type. If you upload a file with an unsupported format, the API returns `400` with type `unsupported_type`:

```json
{
  "error": {
    "type": "unsupported_type",
    "message": "Unsupported file type."
  }
}
```

In a multi-file upload the file is listed in `failed` instead, and the other files are still stored. See [Partial upload failures](/concepts/errors#partial-upload-failures).

## Reserved marker

Files that begin with an internal encryption marker are rejected by the upload endpoint with type `unsupported_type` and `File starts with a reserved marker.` If you encounter this error, the file may be corrupted or use a reserved byte sequence. Try re-exporting the file from its original source.
